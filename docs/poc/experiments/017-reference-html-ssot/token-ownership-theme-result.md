# Attainment status

- **Gate status:** `token-ownership-confirmed`
- **Workflow attainment:** `done`
- **Decision scope:** experimental Reference-Library-internal authoring only;
  no canonical migration, Profile/API freeze, or Consumer distribution.

# Outcome

The existing thin token-only candidate remained useful with a fourth,
responsibility-distinct Reference and complete light/dark coverage on the two
References that define dark designs. Canvas, surface, and focus color have a
common ownership reason, not only equal values. B reduced the reproduced theme
edit from four files/six locations to one file/two locations while keeping
Reference-local changes local and preserving direct browser use.

# Fourth Reference

The new specimen is a 197-line read-only shipment-exception summary workspace.
It differs from shell/navigation, search, and form workflow responsibilities,
yet uses the existing design language without a new business workflow. It has
zero product scripts, one native disclosure scenario, six observed elements,
and no visible or excluded Reference harness root.

# Ownership decisions

| Token | Decision | Evidence |
| --- | --- | --- |
| canvas | Shared | Same application workspace-backdrop responsibility across four light and two complete dark References. |
| surface | Shared | Same primary contained-content responsibility across the same set. |
| focus color | Shared | Same keyboard-focus indicator reason; value changes by theme, while selector, width, and offset remain local. |

No new shared token candidate was added. Text, border, muted/status surfaces,
timeline styling, selectors, typography, layout, focus geometry, and component-
specific theme overrides stay in each Reference.

# Theme boundary

The shared file owns only the light/dark values for the three shared meanings.
Each Reference opts into a theme through its own HTML and keeps all component
rules and overrides local. Common shell and the fourth Reference provide
complete light/dark evidence. Search and form remain their fixed light-only
designs; the result does not invent or claim their dark variants.

# False sharing

The fourth Reference's status accent intentionally equals the shell accent in
both themes. One expresses shipment status/timeline; the other expresses shell
selection/application accent. The local probe changed the former without the
latter or the shared layer. Equal values therefore did not justify common
ownership.

# Maintenance and review cost

- **Common focus probe:** A = 4 files/6 locations/5 validations/4 restore
  writes; B = 1 file/2 locations/5 validations/1 restore write.
- **Detail-local probe:** both = 1 file/2 locations/3 validations/1 restore;
  shared edits and prior-Reference hash changes = 0.
- **Understanding:** A needs one file; B needs the HTML plus one 11-line static
  CSS file. Both are buildless and directly browser-readable.
- **Validation:** sharing reduces synchronization edits, not fan-out review.

# Regression and authority

Five B-to-A comparisons passed with zero errors and zero geometry/extra
diagnostics. Ten positive Conformance checks passed; three retained
Conformance negatives and two comparative negatives continued to fail. The
fourth disclosure completes a keyboard-focused closed/open/closed round trip.
Console/action errors, external/failed requests, CLI/Core changes, Conformance
rules, Consumer requirements, and build/runtime dependencies were all 0.

Forty of 42 PNGs were byte-identical. The remaining two were quantified as
small shell-chevron raster differences while computed observations were exact;
no threshold or exception was introduced. Fixed prior evidence and the
Consumer tree remained hash-identical.

# Problems found and corrected

Self-review corrected a 4.22:1 status-text contrast defect, replaced an
interaction that observed focus without reliably toggling, and removed a
one-pixel open-state trigger shift. It also narrowed an overbroad Consumer hash
guard and prevented supplementary PNG noise from becoming a CLI exception.

# Long-lived knowledge promoted

The cross-experiment note now records the reproduced boundary across four light
responsibilities and two complete dark responsibilities: a very small
Library-local value layer may own canvas, surface, and focus color when their
meaning and change reason remain common across themes. Component selectors,
focus geometry, and theme-specific component styling remain local. Complete
dark support is opt-in per Reference rather than a reason to expand the shared
layer.

# Candidates, human judgment, and next phase

No human design judgment is required for this bounded Gate. The fourth screen
is experimental evidence, not a canonical candidate.

Workspace-scale responsibility-complete References remain promising but are
not a frozen granularity. Composite controls such as DatePicker or Entity
Selector remain possible future granularity probes; atomic TextBox/Button
References may be too fine. Consumer interference, Reference Profile authority,
responsive behavior, other browsers, and real AT remain unconfirmed.

Keep A and B as reversible evidence and do not migrate canonical References.
The next bounded candidate is the already identified part-to-integrated
diagnostic-noise problem: improve reviewer presentation without scope metadata,
suppression, or hidden errors. Do not proceed automatically to MCP, Consumer
token distribution, Profile/API freeze, or a shared primitive.
