# Method and provenance

This is a new experiment for [Torrone issue #68](https://github.com/mk3008/torrone/issues/68). The [previous benchmark](https://github.com/mk3008/torrone/tree/628b5a5d1302ec28d4fbaf02ae0237c94d12ef48/docs/poc/experiments/022-issue68-greenfield) remains on its original branch and commit. The Torrone and private Control repository guidance were consulted. The public issue, previous commit and associated pull-request lists contained no separate review comments for the old experiment when checked. This rerun addresses the archived report's structural scroll assertion, weak isolation, read-only implementation and late Storybook tests, together with the new requirements to use a fully stated prose specification and withhold all oracle feedback.

## Calibration

The original oracle remained byte-identical at SHA-256 `36A2608EFBF23F508207EF0F052B2E0ADE2B6C8CC9975A46E9EE38A2EF0B3FAC`. It replayed at 15/15. The new suite replayed at 25/25 in the benchmark's Linux Chromium. A mutation control passed 21/25 and failed at the expected checks for desktop arrow movement, manual keyboard activation, dotted focus and the narrow row's 6 px gap. The new reference's only preparatory transport change is the same sixth item fixture insertion already used by the original script.

All assertions are associated with shared prose IDs. The old implementation-specific scroll assertion is represented by the change in rendered tab positions and preserved selection. Visual scoring uses visible geometry and sampled screenshot pixels. Tab and button names, selected state and expanded state follow the accessible UI requirements. Exact viewport points and expected vectors remained in the evaluator. The focus rules draw on the manual-activation [WAI-ARIA tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/). The 44 px touch target is the product's design choice, which exceeds the basic size described by [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Isolation and available workflows

The local execution was explicitly approved. Each trial started with a fresh Codex CLI session and a dedicated Docker container containing only its implementation workspace mount. The shell could edit and run code, serve the app locally and drive Chromium. It had no network, Docker socket or mount of the old or new evaluator. The CLI's direct shell, image reader, web search, apps, plugin access and memory were disabled. A container-specific bridge returned screenshots and shell results. The trusted CLI model connection remained on the host and used existing ChatGPT authentication. All trials used the same `gpt-5.6-sol` model, low reasoning and Chromium 158.0.8127.18.

The three arms received the same common brief, fixture and official Lucide assets. Torrone received generic catalog examples and design/implementation guidance. It received none of the old target images or application files. Storybook received the official `ui-workflow` and `component-docs` guidance and an empty Web Components/Vite scaffold with the 11.0.0-beta.1 CLI, Vitest and local review functionality. The unrelated component preflight ran `storybook tools docs list` and passed an official interaction test in Chromium. [Storybook 11 beta](https://storybook.js.org/blog/storybook-11-beta/) · [Vitest addon](https://storybook.js.org/docs/11/writing-tests/integrations/vitest-addon)

The first infrastructure attempt was cancelled by the CLI's per-tool confirmation default before any command ran. Subsequent attempts exposed a Windows UTF-8 and long-command transport issue. Those sessions were stopped and excluded from scoring. The repaired bridge validates a 36 kB command and a Japanese write/read round trip before every scored model session. The design, oracle and score rules were frozen before the first attempt and held through the infrastructure correction. The valid runs used new containers and new agent sessions.

Each arm could ask a question through the bridge. The protocol shares material answers with all arms. First and final submissions were sealed through the bridge. No hidden oracle output was sent back to an implementer. The coordinator administered the environment and did not edit submitted source.
