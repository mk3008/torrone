# Issue 68 rebenchmark protocol

## Fixed sources and independent scope

The previous experiment is commit `628b5a5d1302ec28d4fbaf02ae0237c94d12ef48`. Its assets, oracle and outcomes are historical evidence. Keep its executable oracle unchanged and verify its SHA-256. The new behavioral suite derives its target from that existing executable reference and the shared prose specification. It preserves the observable historical cases while replacing DOM class and scroll-element assumptions with user-observable measurements. New interaction and visual probes are a separate, explicitly mapped assessment. Scores from the old and new suites are different measures.

Before implementation, freeze the shared specification, data, dependencies, browser, test code, reference validation and score definitions. Publish the checksums, while keeping the evaluator and target assets out of all implementation environments until the final handoffs are sealed. The historical branch is public, so disable external access from implementation commands and disable hosted search or connectors that could retrieve it. Verify denial with an outside-file and remote-network canary. Report the trusted model transport and any residual risks separately.

## Treatments

All arms receive exactly the same prose, data and official icons. Each starts with no target app source, stories or tests. General shell, editing and real browser tools are available. Each may use self-authored tests, scripts or screenshots. A dedicated tool's test failures are valid self-review inputs. Shared tooling stays fixed across arms.

- Prompt Only uses the prose and normal developer tooling.
- Torrone may use the generic catalog, relevant guidance, design wizard, fresh concept imagery and review. Exclude every previous image, Reference or source specific to this target screen. A fresh concept, if used, is generated from the common prose only and retained as an arm output. Extra-charge services require separate approval.
- Storybook may use the official Skills, CLI, stories, docs, testing and local review, starting with an empty story project. Choose an officially supported renderer for the test tooling. Pin and disclose versions. No published visual-test service is required.

## Runs and questions

Use the same model, reasoning effort, browser revision and input data across arms. Start each trial with a new session and new isolated workspace. Start with one matched round, then repeat independently when the environment, approved usage budget and time allow. Retain trial-level scores, range and median if repeated. State n explicitly. Each agent may ask product questions. Log the question, answer, source, recipients and time. For a material clarification, provide the same wording to all arms and confirm the specification still covers every scored expectation. No design images, hidden test output, selectors, exact acceptance vectors or hints from another arm are shared.

The first runnable snapshot is saved before self-review. The agent runs its own tests, inspects browser output and repairs it autonomously. Seal the first snapshot and the final handoff with content hashes. Evaluate only after every final handoff in the matched round is sealed. Hidden results never become repair feedback. An implementation coordinator may operate the experimental infrastructure and distribute answers. Any implementation edit by the coordinator invalidates that trial as an independent AI result.

## Measures and stars

Record each test ID, associated prose IDs, verdict and screenshot. A valid run that visibly fails a requirement receives fail. Mark an item N/A only if infrastructure prevented measurement. Display raw pass counts against the fixed denominator, including the N/A count if any. Distinguish all fail from a successful tie. Independent headline rows use desktop fit (5), narrow fit (8), interaction and state (7), and visual conformance (5). Show the 25-case aggregate as context without a second aggregate win.

Visual conformance combines screenshot pixels and displayed geometry. Review overall composition and failed screenshots separately, against the prose and existing reference, with reviewer identity and absent human approval noted. The score does not claim exhaustive visual similarity. Evaluate use of official icon files by inspecting source separately. Preserve a fresh-context review when available.

Quality review reports a separate six-item checklist. Check the documented launch, executable self-tests, no unnecessary runtime dependency, fixture-driven adaptation, readable separation of view and state, and scoped accessibility/keyboard behavior. Keep first-to-final changes and authored self-tests separate from hidden scores. Avoid attributing a causal effect to one feature when the treatment bundles several features.

Record preparation, implementation, autonomous review and evaluation elapsed intervals separately. Capture CLI input, cached input, output and reasoning tokens where available. Report consumption units and currency as unknown without receipts. Document human interventions, questions, repair attempts and unsuccessful tool operations. A shared baseline setup cost is separate from each arm's preparation.

On a comparable row, award ★ to the best verified value. Equal counts share ★ when at least one case passed. If all valid scores are zero, report all fail without stars. Time and token observations within 5% of the best verified value share ★. An unmeasured arm does not tie with any score. Compare final values, and show first-to-final changes separately.

## Public evidence boundary

Release no test source or target assets before sealing implementations. The final Draft PR can include the new benchmark, public reference provenance, reproducible runner and sanitized execution evidence. Keep historical files unchanged. Exclude private Control content, personal paths, credentials and transient tool state. No merge, release, hosted preview deployment or extra-charge operation is part of this benchmark.
