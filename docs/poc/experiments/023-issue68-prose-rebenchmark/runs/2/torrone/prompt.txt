# Document-tab workspace

Implement a new Japanese-language browser workspace for switching between open documents and between sections of the selected document. Use HTML, CSS and JavaScript. Browser target is Chromium. Standard custom elements are allowed. Frameworks and libraries for authoring, testing and developing are allowed. Keep the delivered screen runnable as a standalone local web app using its documented commands. Start with the supplied data. No persistence or backend is needed.

## Page hierarchy

**V1.** Use a light cool-gray page background around a white workspace. Center the workspace, cap its outer width at 1,180 CSS px, and inset its contents by 16 CSS px on both sides. On a narrow screen the workspace spans the screen. The workspace fills at least the viewport height. Use a dark navy system sans-serif body type, around 15 CSS px. Avoid large empty gutters or ornamental elements.

**V2.** Start with the strong page heading 受注ワークスペース and a compact outlined button 作業メニュー in the same header. On a wide screen the button is at the far right of the header. On narrow screens the controls align left and can wrap. Leave 16 CSS px beneath the header. Stack the 文書 and 項目 tab rows directly beneath it, left aligned with zero vertical gap. Place the document content directly below the item row. Use a white bordered panel with gently rounded bottom corners, 20 CSS px of inner padding and at least 210 CSS px height. Its level-two heading is the document and selected item joined by の, such as 請求書の明細. Beneath it show the affiliation, middle dot and selected item, such as 東日本 · 明細. Include the compact outlined button 内容の確認 after the metadata. The workspace and content buttons are focusable fixture controls.

**V3.** The document tabs use gently rounded top corners and flat lower corners. Give eastern documents a pale blue surface and a muted teal top edge. Give western documents a pale purple surface and a muted violet top edge. Keep the order even when regions alternate. Item tabs have a white surface, thin cool-gray borders, and rounded top corners. All tab labels remain on a single line. Align document labels left and item labels centered. A document label only shows its document name. Long names end with an ellipsis and preserve their closing-control slot.

**V4.** Use a strong blue bottom selection line about 4 CSS px thick and a heavier label. Show keyboard focus independently as a dark dotted line inside the focused tab. A focused but inactive tab keeps its regular label weight and never gains the selection underline merely by taking focus. Color references are white `#ffffff`, surrounding gray `#f4f6f9`, text `#162235`, cool-gray control border `#8897ac`, east fill `#e5f2f9`, east edge `#286987`, west fill `#f0e9f8`, west edge `#71469a`, and selection blue `#135ad2`. Small rendering differences are acceptable. The outer surfaces and visual hierarchy should match the description.

**V5.** Desktop tab surfaces are compact, around 40–44 CSS px high. Narrow tab and count controls are around 44 CSS px high. Adjacent controls in one row align to the row's vertical bounds. A tab's × and a count button's chevron are secondary to the label, about 16 CSS px high and vertically centered with the label. Use the supplied official Lucide files without redrawing or merging paths. The clickable close target is about 36 CSS px square on desktop and 44 CSS px on narrow screens. Put the × at the trailing end of its own tab. A count button uses an 8 CSS px label-to-icon gap, thin cool-gray border, white fill and roughly 7 CSS px corner radius.

## State and width rules

**R1.** Start with the configured documents in data order. The first open document is selected initially, with its first section selected. The first document's available items are limited by the selected fixture configuration. Other documents expose their own full item lists. Preserve a document's selected item while switching between open documents.

**R2.** Judge each row separately. First consider the natural single-row width of all its ordinary tabs, without overflow controls. Ordinary document-tab outer widths are 140 CSS px in desktop mode and 124 CSS px in narrow mode. Ordinary item-tab outer widths are 112 CSS px in desktop mode and 86 CSS px in narrow mode. In both rows ordinary tabs are adjacent horizontally without a gap. A row may use the full inner width of the workspace. If the tabs fit exactly or have room to spare, show every tab with no overflow buttons. Recalculate after resizing, changing documents or closing one. A row returns to ordinary full display as soon as it fits. Narrow mode applies through 599 CSS px viewport width, and desktop mode starts at 600 CSS px.

**R3.** On desktop, a row that cannot fit its ordinary tabs retains all tabs in a single horizontally clipped track and adds two compact horizontal arrow buttons alongside it. Arrows move the visible tab range left or right, and wheel input over that row can also move the range. Scrolling the row must preserve the selected document or item. The other row behaves independently. There is no count button on desktop. Do not introduce horizontal scrolling for the entire page.

**R4.** On a narrow screen, an overflowing row displays only its selected tab and a button whose visible text is ほか followed directly by the number of hidden tabs, such as ほか4. Use no horizontal scroll arrows in this state. Give the button the width needed by its label and icon, with no empty stretch. Place it at the right inner edge of the workspace. The selected tab fills all remaining width to its left, leaving exactly 6 CSS px between the two visible outer surfaces. Apply this independently to each row.

## Narrow choosers

**C1.** The document count button has a right-pointing chevron. Activating it opens a separate chooser view that replaces the tab-and-content view until the chooser is dismissed or a document is selected. Show a back action and heading ほかの文書（N）. Show the hidden documents, in open order, as cards in a two-column grid. Each card has a muted thumbnail, a document name, and its affiliation on a separate line. Thumbnails may be simple chart-like placeholders. Include the name and affiliation in the accessible name so the two 受注管理 documents are distinguishable. Leave the already selected document out of the chooser. Selecting a card returns to the workspace, selects its document and recalculates the two rows.

**C2.** The item count button uses a downward chevron when closed and an upward chevron when open. It opens a compact white list immediately below the button with the right edges aligned. Start the list with the hidden item names. Use no intervening heading and leave out the selected item. Selecting an item closes the list, updates the content while preserving the document, and moves the previously selected item into the list. The count does not change.

## Interaction and accessible controls

**I1.** Provide two accessible horizontal tab lists named 文書 and 項目, with selectable tabs and an accessible selected state. Document tabs expose the full name and affiliation to assistive technology even if visually clipped. Use the selected tab as the entry point when tabbing into a tab list. Left and Right move focus to the previous or next tab in the row, wrapping at the ends, without selecting. Enter or Space activates. Use Tab and Shift+Tab to reach neighboring controls. Show the document label and affiliation on hover or keyboard focus when its long label is clipped on desktop. Preserve the position of neighboring tabs while the label details or close control appear.

**I2.** Document close buttons are separate controls. On desktop show the close button on the selected, hovered or keyboard-focused document. On narrow screens show it only on the selected document. Clicking or keyboard-activating it closes that document without activating its tab as a side effect. If it was inactive, preserve the selected document. If it was selected, activate the following document, or the preceding document when there is no following one. Give focus to the following remaining document or the preceding one as appropriate. If there are no documents, show 開いている文書はありません。 and return focus to 作業メニュー.

**I3.** When a chooser opens, move focus into it. Escape dismisses either chooser and returns focus to its trigger. The document chooser's Back action has the same result. Selecting a document card focuses the selected document tab. Selecting an item in the list returns focus to the item count trigger. Expose expanded or collapsed state on count controls. Their accessible names include both the visible count and 文書を切り替える or 項目を切り替える as appropriate. Give the desktop scroll buttons the accessible names 文書を左に送る, 文書を右に送る, 項目を左に送る and 項目を右に送る. Include the document name and を閉じる in close-button accessible names. Keep decorative icons out of accessible names.
